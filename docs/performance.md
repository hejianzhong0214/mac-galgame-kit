# 性能调优

基准机器：MacBook Air M3（8 核 CPU、无风扇）、16 GB 内存、1 TB 存储。

## 这台机器的特点

- **单核性能很强**。galgame 和 2D 小游戏几乎都是单线程瓶颈，即使经过 Rosetta 翻译也绰绰有余。
- **没有风扇**。短时间负载没问题，持续满载十分钟左右机身变热后会降频。调优的重点是别让它白白发热。
- **16 GB 统一内存**。显存和内存共用，对这类游戏足够；只有同时开虚拟机才会紧张。

## 系统层

1. **关闭低电量模式**：系统设置 → 电池。低电量模式会明显限制性能。
2. **全屏运行**：macOS 在游戏全屏时自动启用游戏模式，提高游戏的调度优先级并降低蓝牙手柄、耳机延迟。窗口模式不会触发。
3. **重负载插电**，并把机器放在硬质平面上，不要放在被子或腿上。
4. 玩之前退出浏览器里的视频页面、同步盘等后台负载。

## 路线层

按 README 的三档顺序选。同一个 RPG Maker MV 游戏，原生 NW.js 相比 Wine 里跑 x86 的 NW.js，CPU 占用通常低一半以上，发热和续航差别很明显。

## Wine 层

`gal run` 已经做了这些：

- `WINEDEBUG=-all`：关掉调试输出，这是 Wine 下最常见的无谓开销。
- Retina 模式关闭：游戏按逻辑分辨率渲染，由系统放大。开启后渲染像素数翻四倍，对 3D 游戏是很大的负担，对 2D 游戏画面也不会更清晰（素材分辨率是固定的）。
- `WINEMSYNC=1` / `WINEESYNC=1`：在支持的 Wine 构建（CrossOver、部分第三方构建）上启用更快的同步原语；官方 Homebrew 版会忽略这两个变量，没有副作用。

可以自己再做的：

- **图形后端**（针对 3D 游戏）：D3DMetal 通常最快，其次 DXVK，Wine 自带的 wined3d 最慢。纯 2D 的 galgame 不用管。
- **锁帧**：没有垂直同步的小游戏会跑到几百帧把机器烤热，在游戏设置里打开垂直同步或限制到 60 帧。
- **分辨率**：3D 游戏用 1680×1050 或 1920×1200，画质和发热比较平衡。

## 存储

1 TB 很宽裕。游戏和容器都放内置盘，不要放外接机械盘或网络盘，否则读盘卡顿。每个 Wine 容器约占 1–2 GB，没必要一个游戏一个容器。

## 怎么判断瓶颈

打开活动监视器：

- CPU 一栏某个进程长期接近 100%（单核吃满）→ CPU 瓶颈，考虑换原生路线。
- 窗口 → GPU 历史记录 接近满载 → 降分辨率或锁帧。
- 内存压力变黄或变红 → 关掉其他应用或虚拟机。
